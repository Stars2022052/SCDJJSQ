# 潮汐秘境计算器

《弹壳特攻队》潮汐秘境玩法的辅助计算工具。玩法是「反向扫雷」——目标是找齐钻石，而不是避开雷。

工具做三件事：

1. 你把手里的信息填进去（哪格是数字几、哪格翻出了钻石）。
2. 工具推导出每一格是钻石的**精确概率**。
3. 告诉你下一步点哪里最划算。

---

计算器是**一个 HTML 文件**，CSS 和 JS 全部内嵌，没有任何网络请求、字体下载或第三方库。

## 概率是怎么算的（以及为什么可以信）

### 1. 状态建模

每个格子只有四种状态：未翻开、已翻开的数字（0–8）、钻石、安全。

对每个已翻开的数字格建一条约束：**它周围 8 格中还有几颗钻石没被确定**，以及**这些钻石只能落在哪几个未知格里**。

### 2. 确定性推导

先跑一遍传播，把所有能靠逻辑确定的格子钉死：

- 基础规则：剩余钻石为 0 → 邻格全是安全格；剩余钻石数 = 未知邻格数 → 邻格全是钻石。
- **子集规则**：若约束 A 的候选格集合是约束 B 的子集，则 `B\A` 必须放下 `remB − remA` 颗钻石。这条能覆盖经典的「1-2-1」交叉约束，也是很多简易工具算不出 75%/50% 的原因。

反复迭代到不再有新结论为止。

### 3. 精确枚举

剩下的未知格按约束连通性拆成若干**互相独立的分量**，对每个分量做完全枚举（带剪枝），得到：

- `cnt[k]`：这个分量恰好含 k 颗钻石的合法布局数
- `marg[格][k]`：该格是钻石、且分量含 k 颗钻石的合法布局数

### 4. 全局钻石总数加权

这一步是精确与近似之间的分水岭。

棋盘上的钻石总数是**固定**的（20 / 30 / 45）。设还剩 R 颗没找到，边界格一共占了 K 颗，那么剩下的 `R − K` 颗必须落在**外围格**（不挨着任何数字格的未知格）里，放法有 `C(外围格数, R − K)` 种。

所以任意一个事件的权重是：

```
权重 = Σ_K ( 该事件下边界恰占 K 颗的布局数 ) × C(外围格数, R − K)
```

这等价于「在所有满足全部约束的完整棋盘布局上均匀计数」，是数学上正确的概率。它同时解决了两件事：边界格的精确比值，以及外围格该给多少概率。

这也是「全枚举」和「局部平均」的区别：没有这一步，外围格只能瞎猜一个密度。

### 5. 近似模式的触发条件

极端情况下（未翻开格特别多、约束又特别松），精确枚举的规模会爆炸。此时工具会在约 0.4 秒后自动切到**最大熵近似**（迭代比例拟合：让每一格的概率同时满足所有数字约束与全局总数约束），并在界面上把徽标明确标成 `近似`。

近似模式保留了约束的期望值，但丢掉了相关性，因此**不保证精确**。实际对局中几乎不会触发——见下面的实测。

### 6. 验证结果

算法用「暴力枚举全部合法布局」做了逐格对拍：

| 测试 | 规模 | 结果 |
| --- | --- | --- |
| 随机棋盘对拍（开全局约束） | 200 组 4×4 / 5×5 随机局面 | 逐格误差 **0**（浮点完全一致） |
| 随机棋盘对拍（关全局约束） | 160 组 | 逐格误差 **0** |
| 文档用例：数字 3 + 2 个 × + 2 个已翻开 | — | 四格均为 **75%** |
| 文档用例：数字 1 + 已标 💎 | — | 其余 7 格全部推为 × |
| 子集规则：`<1>` 与 `<2>` 约束 | — | 推出第 3 格为钻石 |
| 矛盾检测 | 角落填 8 | 正确报「无解」 |
| 真实对局形态（12×12 / 45 颗） | 52 次求解 | 最慢 **6 ms**，全部精确 |

也就是说：正常玩下来的局面，枚举都在毫秒级完成，近似模式基本见不到。

## 截图识图

### 现在能做什么

点右上角「截图识图」：

1. 把游戏截图拖进去（或选文件、或直接 `Ctrl+V` 粘贴）。
2. 工具会用投影能量自动估算棋盘的网格范围；不准的话拖四个滑块微调，蓝色网格会实时对齐。
3. **直接在网格里点击**，用和主棋盘一样的标记工具逐格录入。
4. 「应用到棋盘」把结果合并进去。

这条路**不依赖任何模型，100% 不会认错**，代价是要手点一遍。对一局已经进行到一半的棋盘来说，一般十几秒能点完，是目前最实用的方案。

### 关于「训练一个识图模型」

你问的是「识图功能需要训练什么」。结论是：**需要一个小型的单元格分类器**，把棋盘定位和单元格识别拆开看。

**第 1 步：棋盘定位（已经能用，可以不训练）**

现有实现是把截图缩到 340px 宽、转灰度、算每一列/每一行的相邻像素差之和，取能量超过峰值 30% 的区间作为网格外接框。对大多数截图够用。如果以后遇到花哨边框导致不稳，可以训练一个轻量的**四角点回归**模型（输入缩放后的图，输出 4 个角点坐标），数据量需求很小（几百张就够），但优先级不高。

**第 2 步：单元格分类（这才是要训练的）**

对每个格子按对齐结果裁出一小块图（建议 48×48），分类成 11 类：

```
unrevealed │ 0 │ 1 │ 2 │ 3 │ 4 │ 5 │ 6 │ 7 │ 8 │ diamond
```

- **数据**：200–500 张真实截图就够起步。关键是覆盖多样性——不同分辨率、不同地图尺寸、不同进度、不同皮肤/滤镜、深色与浅色背景。
- **标注**：直接用本工具的「截图识图」面板当标注器——对齐后点一遍，导出的 `cells` 就是逐格标签，几乎零额外成本。
- **增强**：亮度/对比度抖动、轻微缩放与旋转（±3°）、JPEG 压缩噪声、模拟不同屏幕的色偏。
- **模型**：MobileNetV3-Small 或自己搭的 4 层小 CNN，输入 48×48，输出 11 类。量化后大约 0.5–2 MB。
- **训练**：PyTorch 训练 → 导出 ONNX → 用 `onnxruntime-web`（WASM）在浏览器里推理。

**第 3 步：接进现有代码**

这一步已经预留好了。`UI` 里的 `shot.cells` 就是逐格的 `Int8Array`，取值和主棋盘完全一致（`-1` 未翻开 / `0`–`8` 数字 / `9` 钻石 / `10` 安全）。识图模型只需要产出这个数组，然后：

```js
shot.cells = modelOutput;   // Int8Array(rows * cols)
renderOverlay();            // 立刻在截图上显示识别结果
```

用户再肉眼扫一遍、点错的格子改掉，按「应用到棋盘」即可。**模型只负责给初稿，人工只负责纠错**——这样即使模型有 90% 准确率也好用。

**为什么现在不直接内置模型**

- 计算器是「单文件、零依赖」的承诺，塞进 1–3 MB 的 WASM 权重会破坏这一点（想做的话，把权重 base64 内嵌，文件会涨到 2–4 MB，仍然离线可用，只是变大）。
- 没有真实截图与标注数据就训练，模型在不同设备、不同皮肤上的泛化会很差，反而比手工点更费时间。

所以当前版本把「对齐 + 点击录入」做扎实，把模型位置留出来。等你攒够几十上百张截图，随时可以补上分类器。

## 定制器

`潮汐秘境定制器.html` 是一个独立的可视化编辑器，**不包含在计算器里**。

打开后：

1. 点「打开计算器文件」，选 `潮汐秘境计算器.html`（或者直接把文件拖进页面）。
2. 左侧按分组列出所有可改的东西：标题文案、棋盘尺寸、概率分级、配色、数字 1–8 的颜色、动效。
3. 右侧是**真实界面的实时预览**，改一下立刻看到效果。
4. 下方是**配置源码**：点哪个字段，就会自动滚动并高亮到文件里对应的那一行——想直接改代码也有据可循。

改完有两种生效方式：

- **应用到本机**：写进浏览器本地存储，刷新计算器页面立刻生效，不改文件。适合自己调着玩。
- **导出新 HTML**：生成一份改好的新文件，适合上传到 GitHub Pages 给别人用。

还有「直接编辑源码」入口，可以在一个文本框里改整个 HTML 然后合并回来。

### 配置结构

计算器里的所有可调项都集中在一个 JSON 块中，位于文件第 10 行附近，被两个注释包着：

```html
<!-- ==== CONFIG:BEGIN ==== -->
<script id="tidal-config" type="application/json">
{ "text": {...}, "board": {...}, "prob": {...}, "color": {...}, "fx": {...} }
</script>
<!-- ==== CONFIG:END ==== -->
```

计算器启动时读取这个块，把颜色写进 CSS 变量、把文案填进 DOM。所以改外观**不需要碰 CSS 和 JS**。

## 二次开发

```
src/
  core.js         推导引擎（纯函数，可单独在 Node 里 require）
  ui.js           界面逻辑
  style.css       样式
  template.html   页面骨架 + CONFIG 块
  customizer.html 定制器
  index.html      首页
build.mjs         把上面拼成单文件
test/
  core.test.mjs       算法暴力对拍
  ui.test.mjs         界面交互端到端
  customizer.test.mjs 定制器端到端
  measure.mjs         布局测量
  preview.mjs         生成真实局面截图
```

```bash
node build.mjs            # 生成 dist/
node test/core.test.mjs   # 算法测试（纯 Node，不需要浏览器）
```

`core.js` 是纯函数、零 DOM 依赖，可以直接 `require` 到别的项目里（比如写个 Discord 机器人）。

## 已知限制

- **标记错了就会报「无解」。** 这是有意为之：所有约束同时满足不了时，工具会明说而不是硬算。撤销一步或改掉错标即可。
- **近似模式不保证精确。** 只在边界特别大的开局阶段可能出现，界面会标出来。
- **不联网、不同步。** 进度只存在本机浏览器里，换设备要用导出/导入存档。
- **识别图案靠人工。** 见上一节，模型位置已预留。
